# 군수실 일정 관리 v2.1.2

일정을 한 번 입력해 일일·주간·월간 일정표를 만들고, 참석 예정자와 준비사항을 함께 관리하는 Windows 데스크톱 프로그램입니다. 외부 서버로 일정을 보내지 않습니다. 인터넷 연결은 사용자가 업데이트 확인·적용을 선택할 때 필요합니다.

## 실무자: 내려받은 뒤 실행하기

1. GitHub Releases의 `GunsuSchedule.exe`를 내려받고 두 번 클릭합니다. ZIP으로 받았다면 먼저 압축을 풉니다.
2. 처음 실행하면 사용자 전용 프로그램 폴더에 복사하고, 화면 준비 후 바탕화면에 **군수실 일정 관리** 바로가기를 만듭니다. 이후에는 이 바로가기를 사용합니다.
3. ZIP에 함께 들어 있는 **처음사용_5분안내.html**로 입력·저장 순서를 확인합니다. 첫 실행 후 바탕화면의 **군수실_일정_출력문서**에도 복사됩니다. 상세 설명과 실제 저장 위치는 **먼저_읽어주세요.html** 또는 **사용설명서.txt**에서 확인합니다.

| 찾을 내용 | 보관 장소 |
|---|---|
| 실행 바로가기 | Windows가 지정한 실제 바탕화면 |
| 일일·주간·월간 한글 파일 | 바탕화면/군수실_일정_출력문서/일일일정·주간일정·월간일정 |
| 사용자가 만든 전체 데이터 백업 | 바탕화면/군수실_일정_출력문서/데이터백업 |
| 원본 일정·메모 | `%APPDATA%/GunsuSchedule/schedule_data.json` |
| 최근 저장 이전 상태 60개 | `%APPDATA%/GunsuSchedule/backups` |
| 프로그램과 이전 버전 | `%LOCALAPPDATA%/GunsuSchedule/versions/<버전>/GunsuSchedule.exe` |
| 오류 기록 | `%APPDATA%/GunsuSchedule/application.log` |

OneDrive나 기관 정책으로 바탕화면이 이동된 경우 Windows Known Folder API로 실제 위치를 확인합니다. 화면 하단과 도움말에서 전체 경로를 확인하고 폴더를 바로 열 수 있습니다. 출력 파일 이름에 저장 시각과 고유번호를 붙여, 한글에서 열어 둔 이전 문서를 덮어쓰지 않습니다.

Windows 10/11 64비트와 Microsoft Edge WebView2 Runtime이 필요합니다. 일반 사용자는 Python·VS Code를 설치하지 않습니다. 기관 보안 정책에 따른 실행 허용은 기관 담당자가 처리합니다. 보안 경고나 통제를 우회하지 마세요.

## 업무 기능

처음 실행하면 접을 수 있는 **사용 순서 안내**가 열립니다. 일정이 없거나 선택한 기간에 출력 대상이 없으면 입력·검색·참석 필터 확인을 안내합니다. 주석과 상세 업무자료 옵션에 맞춰 출력 전 설명도 바뀝니다. 안내 화면은 공식 한글 문서와 인쇄물에 포함되지 않습니다.

- 시작·종료 시간, 군수님/부군수님/일반 행사, 중요도와 확정·미확정·취소 상태.
- 참석 예정자, 담당자·연락사항, 진행·준비사항, 추가 메모, 준비 확인 목록(최대 40개).
- 메모는 기본 한글 파일·인쇄물·CSV에서 제외. 필요한 내부 자료에만 **상세 업무자료 첨부**을 선택.
- 같은 참석 구분의 시간 중복 안내, 지난주 일정 선택 복사, 중복 복사 방지. 복사한 일정은 미확정, 확인 목록은 미완료.
- 검색·상태 필터·목록 페이지, 크게 보기, 최근 변경 30회 되돌리기, 메모까지 유지하는 휴지통.
- 전체 데이터 백업, 복원 전 건수·기간 확인, 자동 백업에서 복구. 백업 JSON에는 내부 메모도 포함.
- A4 세로 일일·주간 / 가로 월간 인쇄. 긴 내용은 연속 행과 페이지로 나누며 각 페이지에 제목을 표시.

## v1 데이터 가져오기

v1/v2 원본 JSON은 시작 시 검증하고 스키마 v3로 읽습니다. 새 출력 주석은 기본 빈 값으로 이전하며 기존 메모는 보존합니다. 저장 시 v3를 기록하므로 미래 스키마를 거부하는 v2.0 앱이 주석 데이터를 덮어쓰지 못합니다. 기존 JSON 백업(이벤트 배열 또는 `events/settings/deletedEvents` 객체)은 **백업·복원**에서 가져올 수 있습니다. 구버전에서 중요도를 참석 구분에 저장한 자료도 변환합니다.

구버전 브라우저 저장소가 같은 실행 환경에 남아 있고 새 원본이 비어 있으면 가져오기 안내를 표시합니다. 구버전 pywebview의 임시 브라우저 저장소는 종료 후 사라질 수 있으며 다른 실행 경로의 저장소를 자동 찾을 수는 없습니다. **전환 전에 구버전에서 데이터 백업을 저장**하는 것이 가장 확실합니다. 구버전의 초기 샘플 데이터는 새 버전에 자동으로 넣지 않습니다.

## 개발 구조

| 파일 | 책임 |
|---|---|
| `schedule_domain.py` / `schedule-core.js` | 데이터 검증·v1 이전 / 화면 날짜·복사·표시 순수 함수 |
| `storage.py` | 동일 폴더 임시 파일, flush/fsync/replace, 저장 순서 확인, 검증된 이전 상태 보관·복구 |
| `app_paths.py` / `installation.py` | 리소스·데이터·출력 경로 분리, 바탕화면 감지, 사용자별 설치·바로가기·중복 실행 제한 |
| `document_layout.py` / `document_engine.py` | 공통 페이지·셀 계획 / HWPX XML·ZIP 생성. 브릿지의 `preview_document`와 한글 저장에 같은 계획 사용 |
| `hwpx_generator.py` / `native_workers.py` | Hancom COM 변환, 반환값·결과 서명 확인, 별도 프로세스와 90초 제한 |
| `bridge_security.py` / `main.py` | 명시한 메서드만 연결, 백엔드 데이터에 기반한 출력, 작업 중 종료 방지 |
| `updater.py` | 고정 GitHub 출처, 크기·SHA256 검증, 버전별 설치, 화면 준비 후 바로가기 전환 |
| `index.html` / `app.js` / `style.css` | 외부 CDN 없는 화면, 저장 성공 이후 상태 반영, 안전한 텍스트 표시 |

프런트엔드 `localStorage`는 원본 저장 수단이 아닙니다. 백엔드가 저장한 스냅샷·revision만 화면 상태로 채택합니다. JS 브릿지에서 임의 URL·파일 경로·쉘 명령을 받지 않습니다. pywebview 6.2.1의 dotted-attribute dispatch는 명시한 메서드와 콜백 ID 검증으로 제한합니다. CSP의 `unsafe-eval`은 pywebview API 생성에 필요하며, 인라인 스크립트·이벤트 속성·외부 리소스는 허용하지 않습니다.

데스크톱 화면은 Edge WebView2가 번들 안의 로컬 파일 URL을 직접 읽습니다. 데스크톱 실행에 로컬 HTTP 서버나 수신 포트를 열지 않습니다. 개발용 브라우저 미리보기만 별도의 HTTP 서버를 사용합니다.

## 실행·검증·빌드

개발용 Python 3.12와 Node 22를 사용합니다.

```powershell
py -3.12 -m venv .venv-build
.\.venv-build\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv-build\Scripts\python.exe -X utf8 run_tests.py
.\.venv-build\Scripts\python.exe main.py
.\.venv-build\Scripts\python.exe -X utf8 build_release.py
```

`run_tests.py`는 임시 폴더만 사용합니다. 실제 APPDATA, 바탕화면, 한글 프로그램을 변경하거나 네트워크에 연결하지 않습니다. 빌드는 테스트 실패 시 중단하고, 완성 EXE를 별도 임시 폴더에서 실행해 저장·재시작·3종 문서 생성을 검증합니다. `dist/GunsuSchedule.exe`, `release/GunsuSchedule-v2.1.2-Windows.zip`, SHA256 및 manifest가 생성됩니다. 역사적 일회성 스크립트는 `tools/legacy/`에 보관했습니다.

브라우저 미리보기는 `python -X utf8 tools/preview_server.py`로 실행하고 `http://127.0.0.1:8765/index.html?preview=1`을 엽니다. 이 개발 전용 서버는 화면 리소스만 제공하고 Python 공통 양식으로 가상 일정을 렌더링합니다. 이 모드는 가상 일정과 메모리 저장만 사용합니다. 일반 브라우저로 HTML만 열어 실제 일정이 저장되는 것처럼 표시하지 않습니다.

## GitHub 배포와 업데이트

개발자용 상세 순서는 [배포·업데이트 안내](배포_업데이트_안내.txt)에 있습니다. 현재 버전의 사용자용 릴리즈 설명은 [v2.1.2 설명](docs/releases/v2.1.2.txt)이며, 빌드가 `release/RELEASE_NOTES.txt`로 준비해 초안 본문에 넣습니다.

Windows GitHub Actions에서 고정 의존성 설치, 테스트, EXE 생성, WebView2 연결 검증, 배포 artifact 보관을 수행합니다. 코드 버전과 같은 `v2.1.2` 태그를 올리면 **초안 Release**를 준비합니다. 관리자가 artifact와 설명을 검토하고 정식 공개해야 앱에서 업데이트로 보입니다. EXE asset 이름은 항상 `GunsuSchedule.exe`입니다.

일반 사용자에게는 `GunsuSchedule-v2.1.2-Windows.zip`을 안내합니다. 앱 내 갱신을 위해서는 `GunsuSchedule.exe`를 별도 Release asset으로도 첨부해야 합니다. 원본 소스와 버전 태그를 먼저 반영하고, `app_info.py`의 `VERSION`과 태그를 일치시킵니다. 이후 수정은 새 버전 번호로 배포하며 공개된 같은 버전의 실행 파일을 바꾸지 않습니다.

업데이트는 정식 세 자리 SemVer만 적용하며 prerelease는 제외합니다. GitHub API asset digest가 없거나 파일 크기·해시·출처가 다르면 실행하지 않습니다. 새 버전을 별도 폴더에 두고 기존 EXE는 보존합니다. 새 화면과 데이터가 준비되고 바로가기 저장에 성공한 뒤 활성 버전을 바꿉니다. 새 프로세스가 종료되면 이전 버전 재실행을 시도하고, 시작 확인이 지연되면 실패 안내를 남깁니다. 이전 데이터 스키마를 덮어쓰는 자동 다운그레이드는 하지 않습니다.

## 검증의 범위와 운영 주의

원자적 교체와 이전 상태 백업은 저장 도중 오류에 대한 방어이며, 디스크 고장·전체 사용자 폴더 삭제·동기화 충돌·모든 백업의 손상까지 데이터 손실을 완전히 막지는 못합니다. 중요한 업무 데이터는 기관에서 허용하는 별도 위치에도 정기적으로 백업하세요. 읽을 수 있는 백업이 없으면 원본을 보존하고 복원 전용 상태로 시작합니다.

HWPX는 ZIP CRC·XML 파싱·셀 주소·행/열 수·미리보기 갱신을 자동 검증합니다. 이는 모든 한글 버전에서의 실제 렌더링 인증을 의미하지 않습니다. 기관에서 사용하는 한글 버전으로 다량 일정·긴 메모·월간 가로 출력·인쇄를 확인해야 합니다. 기본 출력은 **실제 HWP 5 형식**이며, HWPX는 별도 선택입니다. HWP 변환에는 HWPX를 열 수 있는 Windows 한글과 자동화 사용이 가능한 환경이 필요합니다. 등록된 자동화 보안 모듈이 없으면 한글의 정상 파일 접근 승인창을 표시해 사용자가 직접 승인합니다. 실패·시간 초과·잘못된 결과 파일은 **HWP 저장 실패**로 반환하고 HWPX 중간 문서를 보존합니다. 파일 헤더 서명·버전·DocInfo·BodyText/Section0를 검사한 경우에만 HWP 저장 성공으로 처리합니다. 이 구조 검사는 본문의 실제 렌더링 인증을 대신하지 않습니다. 시간 초과에는 변환 작업 프로세스만 종료하며 사용자의 한글 프로세스를 일괄 종료하지 않습니다.

배포 SHA256은 다운로드 무결성을 확인합니다. 게시자 전자서명이나 GitHub 계정 탈취에 대한 별도 신뢰 보증을 제공하지 않습니다. 기관 배포 확대 전 코드 서명과 내부 배포 정책을 검토하세요.

한글 파일 접근 승인과 모듈 설정은 [한컴 공식 개발 안내](https://developer.hancom.com/en-us/hwpautomation)를 따릅니다. 프로그램에서 승인창을 자동 클릭하거나 보안 설정을 변경하지 않습니다.

## 기관 양식과 주석 출력

- 일간: 바깥 테두리, 보은군 표어, 큰 제목, 시간·행사명·오른쪽 장소. 주말은 토·일 한 장 묶기; 과밀하면 별도 페이지.
- 주간: 기존 5개 물리 열과 7개 논리 열 너비 보존. 일자 셀은 같은 날짜끼리 페이지 안에서 병합. 참석 색상과 중요도 분리.
- 월간: 가로 A4, 월요일 시작, 연한 날짜 머리글, 좁은 주말 칸. 실제 달력 계산으로 월초·월말과 윤년 포함.
- `annotation`은 600자까지의 출력 주석. 기본 비출력이며 ‘출력 주석 포함’에서만 행사 아래 표시.
- 상세 메모는 ‘상세 업무자료 첨부’에서 별도 참고자료 페이지로 출력. 날짜별 공식 표에 수천 자 메모를 직접 끼워 넣지 않음.

양식은 첨부 화면의 구조를 기준으로 구현했습니다. 이미지에서 확인할 수 없는 원본의 글꼴·탭·프린터 설정까지 복제한 것은 아닙니다. 실제 기관 한글에서 최종 문서와 인쇄를 확인해야 합니다.
