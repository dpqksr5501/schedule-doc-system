# 실행기 구조와 이전 계약

`Desktop/*.lnk → launcher/GunsuLauncher.exe → active.json → versions/<버전>/군수실 일정 관리.exe`

실행기 프로토콜 1은 앱 버전과 독립적입니다. 실행기는 `active.json`의 경로·버전·SHA256을 검증하며 코드에 컴파일된 앱 버전으로 실행 대상을 고르지 않습니다. 현재 파일이 손상되면 검증된 `previous`를 선택하고, 설치 기록 손상에는 `active.json.bak`을 사용합니다. 설치 경로 밖의 파일은 실행 대상으로 받지 않습니다.

## 역할

- `launch_registry.py`: 실행기와 앱 사이의 작은 JSON 계약 및 파일 검증.
- `launcher_main.py`: 고정 실행 진입점, 업데이트 프로세스 감시와 이전 버전 복구.
- `updater.py`: GUI의 백그라운드 배포 확인·다운로드·해시 검증, 고정 실행기로 반영 위임. 2.1.3에 배포된 이전 감시기와 같은 준비 마커도 유지합니다.
- `installation.py`: 버전별 앱 복사, 포함된 실행기 검증, 준비 완료 후 활성 포인터 전환. 같은 프로토콜의 유효한 실행기는 다시 덮어쓰지 않습니다.
- `desktop_entries.py`: 기존 EXE와 LNK를 이름과 독립적으로 식별하고 이전합니다.

## 전환 순서

1. 실행 중인 프로그램은 원래 일정 저장소를 사용한 채 새 EXE를 별도 버전 폴더에 내려받습니다.
2. 새 EXE는 자신을 감시하는 구버전 프로세스 연결을 유지하며 일정 저장소를 읽습니다. 여기서 실패하면 새 GUI를 만들지 않고 이전 버전으로 돌아갑니다.
3. 화면과 데이터가 준비되면 포함된 고정 실행기를 검증·배치하고 대표 바로가기를 연결합니다. 기존 사용자 이름과 업데이트를 시작한 실제 파일의 경로를 참고해 대표를 선택합니다.
4. 활성 포인터와 직전 설치 기록을 원자적으로 저장합니다. 초기 바로가기 이전에 실패하면 이전 활성 포인터를 복원합니다. 이미 고정 실행기에 연결된 정상 상태에서는 포인터만 갱신합니다.
5. 준비 마커를 알린 뒤 별도 정리 프로세스가 중복 EXE와 LNK를 보관합니다. 선택된 바로가기와 일정·출력 폴더는 정리 대상이 아닙니다.

## 식별·보관 범위

사용자 바탕화면의 최상위 EXE와 LNK를 확인합니다. 실행 파일 크기와 SHA256이 관리 폴더의 확인된 프로그램과 일치하거나, 바로가기 대상이 그 프로그램 또는 고정 실행기일 때만 앱 항목으로 봅니다. LNK의 사용자 지정 실행 인수가 있으면 자동 변경하지 않습니다. 심볼릭 링크·재분석 지점·다른 프로그램·확인할 수 없는 파일은 유지합니다. 임의의 다른 폴더와 공용 바탕화면 전체를 검색해 정리하지 않습니다.

보관은 원본 복사, SHA256 대조, 원본의 변경 여부 재확인, 바탕화면 항목 제거 순서입니다. 파일 잠금은 제한된 재시도 후 다음 실행으로 미룹니다. 결과는 `updates/desktop-migration.json`, 원본은 `updates/desktop-entries/<해시>/<기존 이름>`에 남습니다.

일정 JSON, 일정 백업, 출력 문서는 이 이전 작업의 이동·삭제 대상에 포함하지 않습니다. 처음 내려받은 설치 파일을 임의의 다른 폴더에 둔 경우 그 파일까지 자동 정리하지 않습니다.
