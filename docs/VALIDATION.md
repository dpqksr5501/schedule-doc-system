# v2.1.0 검증 기록

검증일: 2026-10-02. Windows 11 64비트, Python 3.12.14,
pywebview 6.2.1, pywin32 312, PyInstaller 6.22.3 환경에서 수행했습니다.
최종 EXE와 ZIP의 SHA256·크기는 `release/release-manifest.json`에 기록합니다.

## 배포 실행 파일 검사

`build_release.py`에서 완성 EXE를 다시 실행해 아래 항목을 별도 임시 폴더에서 확인했습니다.

- 일정·메모 저장 후 새 API 인스턴스로 다시 읽기.
- 일일·주간·월간 HWPX 생성과 압축 무결성, 내부 메모 제외.
- 출력 하위 폴더와 경로가 반영된 HTML·텍스트 사용설명서 생성.
- 사용자별 버전 폴더 설치와 Windows `.lnk` 생성, 바로가기 대상 경로 확인.

`--ui-smoke-test`는 실제 Edge WebView2에서 로컬 HTML/CSS/JS를 읽고
Python 브릿지 호출, 일정·메모 저장과 재조회, CSP 및 공개 API 목록을 검증했습니다.
개발 도구의 제한 실행 환경에서는 WebView2가 동작하지 않아, 이 검사는 제한을 풀고
별도 테스트 폴더에서 수행했습니다. 앱의 Windows/Edge 보안 설정은 변경하지 않았습니다.

HWP 기본 출력으로 수정한 최종 EXE를 다시 빌드하고 같은 WebView2 검사를 통과했습니다.
최종 EXE의 `--convert-hwp` 작업 프로세스를 유효한 HWPX로 실행해,
한글 COM이 없는 현재 환경에서 실패 안내가 반환되고 잘못된 HWP를 남기지 않는 것도 확인했습니다.

## 화면 조작 검사

실제 브라우저의 명시적 미리보기 모드에서 1380×920 및 940×650 창 크기를 확인했습니다.
메모 입력·체크리스트 완료 상태 저장·다시 열기, 삭제 확인·휴지통 이동·되돌리기,
월간표 묶음 표시와 페이지 분할을 확인했습니다. 최종 최소 크기 검사에서 전체 화면의
가로 넘침이 없었으며 가로 A4 문서는 미리보기 영역 안에서 스크롤했습니다.
HWP 기본 버튼으로 변경한 뒤 940×650 화면에서도 버튼 전체가 표시되고,
HWP가 기본 강조 버튼이며 문서 전체의 가로 넘침이 없는 것을 재확인했습니다.

## 별도 현장 확인이 필요한 항목

- 이 PC에는 한글 COM이 등록되어 있지 않아 **실제 한글 버전별 렌더링과 HWP 변환은 검증하지 않았습니다**.
  XML/ZIP 구조 검사와 변환 실패 경로 검사가 한글 호환성 인증을 대신하지 않습니다.
- 기관에서 사용하는 한글로 긴 행사명·내부 메모·다량 일정·월간 가로 출력·실제 A4 인쇄를 확인해야 합니다.
- 실제 GitHub 공개 Release로 새 버전을 내려받고 재시작하는 운영 환경의 갱신 검사는 아직 수행하지 않았습니다.
  배포 workflow는 태그가 올라오면 검토용 초안 Release를 만들도록 구성했습니다.
- 정전·디스크 고장·동기화 충돌·모든 백업 삭제에 대한 데이터 무손실을 보증하지 않습니다.
  원본 폴더와 별개인 기관 허용 저장소에 전체 JSON 백업을 보관하는 운영 절차가 필요합니다.

## 첨부 기관 양식 반영

일간(평일/주말 묶음), 주간, 월간은 `document_layout.py`의 페이지·셀 계획으로 분리했습니다.
실제 데스크톱의 `preview_document`와 HWPX 생성이 같은 계획을 사용합니다.
새 검사 9개로 일간 프레임·시간 간격, 토/일 자동 범위와 과밀 시 분리,
주간 날짜 셀 병합과 참석 색상, 월간 4~6주·윤년·월초/월말 포함,
공식 문서/출력 주석/상세 참고자료의 분리, 긴 주석·메모 보존과 모든 표 셀 주소를 확인했습니다.
화면과 XML의 폭·셀 개수·페이지 수를 같은 계획과 대조했습니다.

기관 한글에서의 실제 렌더링은 미검증입니다. 스크린샷으로 알 수 없는
원본 글꼴·탭·프린터 설정까지 동일하다는 보증을 하지 않습니다.

최종 v2.1.0 EXE의 자체 검사 및 WebView2 검사도 통과했습니다.
새 `preview_document` 호출의 계획과 실제 JS/Python 저장·재조회가 연결되는 것을 확인했습니다.
브라우저 조작에서는 출력 주석 수정·저장, 기본 공식 페이지에서 상세 메모 제외,
참고자료 페이지에서 상세 메모 포함, 토요일 파란 날짜·일요일 빨간 날짜의 한 장 묶음,
주간 날짜 병합과 주석의 작은 회색 글씨, 2026년 8월의 6주 달력을 확인했습니다.
미리보기 확대/축소는 화면에만 적용되고 인쇄에서는 해제합니다.
저장 형식 v2에서 v3으로 이전하며 기존 업무 메모를 보존하는 검사도 포함했습니다.

## 처음 사용 안내와 설명서

`처음사용_5분안내.html`과 상세 HTML/TXT 설명서를 배포 ZIP에 동봉하고,
정상 실행 시 바탕화면 출력 폴더에도 준비하도록 연결했습니다.
기존 출력 폴더·재시작 검사에서 상세 설명서의 짧은 안내 링크와 대상 파일 존재를 확인하며,
배포 EXE의 자체 검사에서도 안내 리소스가 실제 포함되는지 확인합니다.

브라우저의 격리된 빈 데이터 미리보기에서 안내 버튼 → 첫 일정 등록 → 저장,
짧은 주석·상세 업무자료 선택 시 안내 변화, 접은 안내 유지,
다른 날짜에서 출력 대상이 없을 때 전체 일정 검색으로 이동하는 흐름을 확인했습니다.
940×650 창에서 화면 가로 넘침이 없고 첫 일정 입력 버튼이 화면 안에 보였습니다.
도움말과 안내는 `no-print` 요소이며 문서 생성 계획에 들어가지 않습니다.

47개 Python 검사 및 JavaScript 검사, 새 EXE 자체 검사와 실제 WebView2 저장·재조회·문서 미리보기
검사를 모두 통과했습니다. ZIP의 안내 HTML/TXT를 원본과 바이트 단위로 대조하고 ZIP CRC도 확인했습니다.
이번 변경 후 실제 기관 프린터에서 설명서 인쇄는 검증하지 않았습니다.
